## 1. Executive Security Architecture Overview

The administrative surface of 'M&B Atelier' has undergone a comprehensive cybersecurity hardening overhaul. The legacy administrative portal and all public-facing administrative markers have been eradicated from the public DOM, routing tables, and client bundles. 

Access is governed by a **Zero-Trust Role-Based Access Control (RBAC)** gateway enforcing:
1. **Reconnaissance Thwarting & Route Obscuration:** Traditional paths (`/admin`, `/wp-admin`, `/dashboard`, `/login`, etc.) return authentic Apache/Ubuntu 404 Honeypot responses.
2. **Multi-Channel Obscured Entry:** Hidden gateway access via secret token queries, URL fragments, or keyboard chord combinations.
3. **Step-Up Multi-Factor Authentication (MFA):**
   - **Method A:** RFC 6238 compliant Time-Based One-Time Password (TOTP) compatible with Google Authenticator / Authy.
   - **Method B:** Encrypted SMS / WhatsApp OTP pipeline routed to administrative telephone number `03015466674` (`+92 301 5466674`).
   - **Method C:** Transactional Email OTP routed to `admin@mbatelier.shop` / `babarbuttgrt@gmail.com`.
   - **Method D:** Single-use Emergency Break-Glass Recovery Protocol using offline cryptographic codes.
4. **Anti-Brute-Force Rate Limiting:** 3 failed attempts result in a strict 30-minute lockout.
5. **Session Isolation:** Cryptographically signed HMAC-SHA256 JWT tokens containing `role: "ADMIN_SUPER"`, an automatic 15-minute inactivity idle auto-lock, and strict token revocation blacklisting upon logout.

## 2. Administrator Access Runbook (How to Access the System)

Authorized personnel must execute the following procedures to access the Master ERP Operations Suite:

### Step 1: Navigating to the Obscured Gateway
Because all public links and buttons have been removed from the website navigation and footer, authorized administrators must utilize one of three secure entry channels:

1. **Direct Secret Gateway URL Parameter:**
   Append the secure gateway token to the storefront URL:
   ```
   https://mbatelier.shop/?sec_portal=gateway-portal-x99
   ```
   *(Note: The system automatically purges the parameter from browser history immediately upon loading using `history.replaceState` to prevent shoulder-surfing and URL history disclosure).*

2. **Secret Gateway URL Fragment:**
   Navigate directly via hash fragment:
   ```
   https://mbatelier.shop/#gateway-portal-x99
   ```

3. **Stealth Administrative Keyboard Chord (From Any Storefront Page):**
   While on the storefront, press the administrative key combination:
   - **Windows / Linux:** `Ctrl` + `Shift` + `A`
   - **macOS:** `Cmd` + `Shift` + `A`

*Attempting to navigate to `/admin`, `/wp-admin`, or `/login` will trigger the Honeypot 404 response. Do not use standard administrative URLs.*

### Step 3: Multi-Method 2FA Selection & Verification

The administrator can select from four independent verification channels:

#### Channel A: Google Authenticator / Authy (TOTP — Recommended)
1. Select the **Google Authenticator** tab.
2. If configuring a new device, scan the high-contrast dynamically rendered QR Code into Google Authenticator or Authy.
   - Provisioning URI format:

4. Enter the 6 digits into the TOTP input field and click **"Authenticate with TOTP"**.
   - *The engine supports RFC 6238 HMAC-SHA1 dynamic truncation with a ±30-second time drift window.*

#### Channel B: WhatsApp / Mobile SMS OTP
1. Select the **WhatsApp / SMS** tab.
2. Click **"Dispatch OTP to +92 301 ***6674"**.
3. A cryptographically generated 6-digit code is dispatched to administrative line `0301 5466674`.

5. Input the 6-digit verification code and click **"Verify Mobile OTP"**.

#### Channel C: Email OTP
1. Select the **Email OTP** tab.
2. Click **"Send Verification Code"**.
3. A 6-digit OTP code is dispatched to `admin@mbatelier.shop`.

## 3. Emergency Break-Glass Recovery Protocol

If an administrator has lost access to their mobile device, Google Authenticator, and email simultaneously, emergency break-glass recovery must be used.

### Protocol Rules & Constraints
- Break-glass recovery codes are **single-use** and **cryptographically burned** upon redemption.
- Once redeemed, a code cannot be reused under any circumstances.
- All break-glass redemption events are immutably logged.

### How to Execute Break-Glass Recovery:
1. Open the Zero-Trust Gateway via `Ctrl` + `Shift` + `A` or `?sec_portal=gateway-portal-x99`.
2. Complete Step 1 Primary Authentication.
3. In Step 2, switch to the **"Break-Glass Code"** tab.
4. Input one unused Emergency Recovery Code (e.g. `MBA-9X82-K7L1`).

6. The engine validates the code, burns it from the ledger, clears any active account lockouts, and issues an immediate `ADMIN_SUPER` session.
7. Upon entry, the administrator must immediately re-bind Google Authenticator or update contact information.

## 4. Technical Safeguards & Mitigations Matrix

| Vulnerability Class | Vector & Attack Surface | M&B Atelier Architectural Mitigation |
|---|---|---|
| **Reconnaissance / Enumeration** | Scanners targeting `/admin`, `/wp-admin`, `/dashboard`, `/login` | Intercepted by `Honeypot404` component returning Apache 404 response with `Apache/2.4.52 Server at mbatelier.shop Port 443`. Zero routes advertised in sitemap or DOM. |
| **Cross-Site Scripting (XSS)** | Injection via search bars, review submissions, and order forms | Complete HTML entity encoding (`&lt;`, `&gt;`, `&quot;`, `&#x27;`, `&#x2F;`) via `sanitizeHtml` and `securityService.sanitizeData()`. Strict CSP meta tag: `default-src 'self'`. |
| **Broken Access Control & IDOR** | Manipulating URL query params `/api/orders/history?uid=...` | `getCustomerOrders(uid)` enforces token ownership verification: non-matching customer queries are strictly blocked unless bearer holds `ADMIN_SUPER` role. |
| **Cross-Site Request Forgery (CSRF)** | Unauthorized state mutations via cross-site requests | Cryptographic `X-CSRF-Token` required on state mutations; session cookies configured with `SameSite=Strict; Secure;`. |
| **Brute Force & Credential Stuffing** | Automated credential spray on admin entry | Failed attempt counter: 3 consecutive failed attempts trigger an automated 30-minute system lockout with active countdown. |
| **OTP Flooding / Exhaustion** | Repeated generation of SMS/Email OTP codes | Strict rate limiting: max 3 OTP dispatches per 10-minute sliding window with a 60-second cooldown timer. |
| **Information Disclosure** | Stack traces, debug flags, console messages | All `console.log`, `console.warn`, and `console.error` calls eliminated. Silent operational handling in production. |
| **Session Hijacking / Stale Sessions** | Abandoned administrator workstations | 15-minute idle inactivity auto-lock tracker monitoring mouse, keyboard, touch, and scroll events. |

## 5. Security Maintenance & Rotation Schedules

1. **TOTP Seed Key Rotation:** Recommended every 180 days. Rotate via `securityService.generateBase32Secret()`.
2. **Break-Glass Code Replenishment:** When 3 or fewer recovery codes remain, a new cryptographic block must be provisioned and recorded in the physical vault.
3. **Audit Trail Review:** Review OTP dispatch logs and failed attempt telemetry prior to major seasonal promotional events.
